AtherChain Updated
Backend Migration Report

Scope: existing Updated screens only. Backend and Expo Old were used as read-only references.

Verification is not production certification. The dedicated migration checks, typecheck, style audit and cross-platform JavaScript exports pass. The entire legacy test suite does not pass. No live financial/security mutations or native-device tests were performed.

1. Scope and presentation

  • Application-source changes are in AtherChain-2.0/Expo Updated. Backend and Expo Old source files were not modified.
  • The managed root preview workflow starts the Updated app on port 5000. This hosting configuration is outside the application source.
  • The user explicitly chose “Preserve updated screens only.” No password-recovery, account-deletion, vault-management or other old-app-only screens/navigation were added.
  • Original theme constants, assets, fonts and style definitions were retained. An AST audit compares every JSX style expression and StyleSheet.create definition against the imported baseline in all 36 changed TSX files.
  • Approved exceptions: misleading practice/demo copy was corrected; document number and document expiry inputs were added using existing KYC field styling. Data and status text now reflect the backend. This is not a claim of pixel-for-pixel screenshot equivalence.
  • Existing Expo SDK 58 and core dependency versions were retained. Required additions: Expo-compatible expo-crypto, expo-secure-store, and react-native-passkey. The lockfile was updated.

2. Real integrations

Web calls go through a same-origin /api proxy; native calls use the real API endpoint already configured in Expo Old. Optional explicit API configuration is documented in replit.md. Errors do not silently create demo success results.

3. Demo behaviour replaced

  • Local-only entry, canned banned-login matching, practice OTP/password success and fixed accepted/rejected security codes.
  • Simulated mining accrual, local claim balances/history and local boost counts.
  • Sample contacts, wallet transactions and editorial news; hardcoded referral values and fake security/session stores.
  • Fabricated send references, delayed success before confirmation, assumed 1:1 swap results and nonfunctional receipt share actions.
  • Local KYC rejection/approval deadlines and face completion without an actual captured image.
  • Seeded support conversations, local-only profile saves and local-only inbox read state.

Pure formatting, keypad interactions, animation timing, balance masking and appearance preferences remain client-side because they are presentation behaviour, not simulated backend operations. Compatibility names such as useDemoSession are retained where existing navigation imports them; their implementation requires real authentication.

5. Remaining limitations and risks

  1. No live mutations were used to verify this migration. Login/security changes, registration, financial transfers/swaps, KYC submissions and support creation were not executed against real accounts. Signed-in UI and native-device behaviour remain unverified.
  2. Legacy regression suite is not green. Outdated demo tests need migration; the existing contrast issue was deliberately not changed because appearance must remain intact. Passing dedicated checks do not prove all possible flows.
  3. Backend payment guarantees are limited. It provides neither an idempotency key nor an atomic locked-quote/slippage contract. Client locks prevent duplicate taps and block retries after uncertain results, including reopened sheets. A restart/new session is not proof of rollback: check server history first. Quote metadata after execution is authoritative.
  4. Unsupported API features remain unsupported. Saved items and total-strike rewards have no backing endpoints; the UI states this or displays an unavailable marker. No fake totals were inserted. No old-app-only screens were added, per the user's decision.
  5. Backend constraints were not rewritten. Transfers are internal ATH transfers only. Support accepts one image per message, not multiple attachments or video. Transfer notes are not persisted by the backend. The public appeal endpoint requires identity fields absent from Updated's public help form, so that form does not fabricate an anonymous submission.
  6. Upstream fallback behaviour still exists outside scope. The backend hardcodes WATH balance to zero, contains an incomplete fixed-token swap implementation, and its transaction controller can return an empty successful response on a database error. This app uses the implemented AT→ATH path and cannot distinguish an intentionally empty list from that hidden backend failure.
  7. Native configuration requires real deployment setup. The public EAS project ID, native package identifiers and associated domain were carried over from Expo Old. Push delivery still depends on correct platform credentials, permission and a suitable build. Native passkeys need a development/release build, correct signing/domain associations and backend RP/origin configuration; browser passkeys also require an allowed secure origin. Expo Go is not proof of support.
  8. KYC is not an automated biometric verdict. Camera prompts capture real images and submit the face frame, but no automated liveness algorithm was added or claimed. Approval/rejection remains the backend review's responsibility.
  9. Nothing was published. Preview startup and JavaScript exports were checked; a production deployment was not configured or verified.
